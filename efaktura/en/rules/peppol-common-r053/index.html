E-invoice rule Peppol BIS Billing 3.0

PEPPOL-COMMON-R053: A Danish SE number should look like DK followed by 8 digits

A Danish SE number should look like DK followed by 8 digits.

Check my invoice Create an e-invoice

What the rule says

Danish ERSTORG number (SE) MUST be stated in the correct format.

Source of the quotation: Peppol BIS Billing 3.0 (OpenPEPPOL, peppol-bis-invoice-3)

Why the validator reports it

The rule belongs to Peppol BIS Billing 3.0. Our checker runs it only when the value of cbc:CustomizationID (BT-24) starts with urn:cen.eu:en16931:2017#compliant#urn:fdc:peppol.eu:2017:poacc:billing:3.0.

Profile: Peppol BIS Billing 3.0

How we rate it: warning

Where we point in the file: /Invoice/cac:AccountingSupplierParty/cac:Party/cbc:EndpointID

How to fix it

  1. Open the XML file and find the element cac:Party/cbc:EndpointID.
  2. Add or correct the value the way the wording of the rule above asks for.
  3. Save the file and check it again. The checker runs in your browser, the file is never uploaded.

A correct UBL 2.1 snippet

<cac:Party
    xmlns:cac="urn:oasis:names:specification:ubl:schema:xsd:CommonAggregateComponents-2"
    xmlns:cbc="urn:oasis:names:specification:ubl:schema:xsd:CommonBasicComponents-2">
  <cbc:EndpointID schemeID="0245">2120000001</cbc:EndpointID>
</cac:Party>

The snippet is only the part of the document the rule is about, and the values in it are made up. Put it in the right place inside your invoice; the namespaces are written here only so that the snippet reads on its own.

Check the whole file

The checker runs 332 rules at once and shows the rule code, a plain sentence and the path to the element for every finding. The file is read in your browser and never uploaded. Free, no account.
