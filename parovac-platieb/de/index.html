01

Drei Dinge, die beim Abgleich von Hand am häufigsten Zeit kosten oder schiefgehen.

Einen Kontoauszug mit einer Rechnungstabelle Zeile für Zeile zu vergleichen, geht, ist aber bei mehr Rechnungen langsam und fehleranfällig.

  1. Abgleich von Hand dauert Stunden.

    Den Auszug Zeile für Zeile durchzugehen und zu suchen, welche Zahlung zu welcher Rechnung gehört, ist bei Dutzenden Rechnungen im Monat Routine für einen ganzen Nachmittag, bei der leicht etwas durchrutscht.

  2. Der VS wird falsch eingetragen.

    Der Kunde vertauscht eine Ziffer, lässt die führende Null weg oder trägt den VS gar nicht ein. Ohne übereinstimmenden VS landet die Zahlung heute oft einfach im Stapel „noch zu klären“.

  3. Überzahlungen und Teilzahlungen gehen verloren.

    Wenn ein Kunde einen anderen Betrag zahlt oder eine Rechnung auf zwei Zahlungen aufteilt, wird sie beim Abgleich von Hand leicht als unbezahlt markiert, obwohl sie beglichen ist.

03

Vier Funktionen. Rechnungen und Kontoauszug rein, vier Listen raus.

Kein Server, kein API-Schlüssel, keine Registrierung. parovac.js ist reines JavaScript ohne Abhängigkeiten: lesen Sie es, forken Sie es oder führen Sie es in Ihrem eigenen Code oder in der CI aus.

parovac.js 0 Abhängigkeiten 
import { parseInvoices, match, report, toCsv, MATCHED_COLUMNS,
         paymentsFromCamtRows } from '../parovac.js';
import { parse, toRows } from '../camt053.js';
// alebo globálne: const { parseInvoices, mapColumns, match, report, toCsv } = window.Parovac;

const invoices = parseInvoices(textZExcelu).invoices;
const payments = paymentsFromCamtRows(toRows(parse(camtXmlText)));

const result = match(invoices, payments, {
  tolerance: 0.01,       // EUR, default 0.01
  dateWindowDays: 45,    // default 45
});

const rep = report(result);
// rep.matched, rep.partial, rep.overdueInvoices, rep.unmatchedPayments, rep.markPaid, rep.summary

const csv = toCsv(rep.matched, { columns: MATCHED_COLUMNS });

Das Parsen des Auszugs, das Parsen der Rechnungen und der Abgleich selbst laufen genau so, wie das Formular oben sie aufruft, in Ihrem Browser. Es gibt kein Backend und keinen API-Schlüssel, der den Inhalt des Auszugs oder der Rechnungen irgendwohin übertragen könnte.

Abgleich: ein variabilný symbol und ein Betrag, der innerhalb der Toleranz übereinstimmt, gelten als Treffer; derselbe VS mit einem anderen Betrag als Teilzahlung oder Überzahlung; ohne übereinstimmenden VS wird ein eindeutiger Treffer über den Betrag und die Nähe des Datums zur Fälligkeit gesucht und als Vorschlag markiert; der Rest bleibt ohne Zuordnung. Zahlungen mit demselben VS werden vor dem Abgleich summiert (Teilzahlungen).

Die Kopfzeilenvorlagen für Pohoda, Omega, Money S3, SuperFaktúra, iDoklad und Fakturoid sind eine Schätzung dieser Seite auf Basis üblicher Exporte, keine geprüfte Spezifikation der Hersteller. Einen Fall, den das Tool falsch bewertet, melden Sie bitte als Issue auf GitHub.

05

Fragen, nach denen Leute wirklich suchen.

Direkte Antworten auf Fragen zum Abgleich eines Kontoauszugs mit Rechnungen.

Welche Dateien brauche ich?

Einen Kontoauszug als camt.053 XML (der Standardexport in die Buchhaltung bei Tatra banka, SLSP, VÚB und ČSOB) oder dessen CSV-Export aus dem Schwestertool camt.053 nach Excel. Und eine Liste ausgestellter Rechnungen: Text aus Excel kopiert oder eine hochgeladene CSV-/TSV-Datei, idealerweise mit Kopfzeile (Rechnungsnummer, VS, Betrag, Fälligkeit, Kunde). Ein Export aus Pohoda, Omega, Money S3, SuperFaktúra, iDoklad oder Fakturoid funktioniert, die Spalten werden anhand der Kopfzeile erkannt und lassen sich bei Bedarf von Hand ändern.

Wie wird ohne VS abgeglichen?

Wenn eine Zahlung mit keiner Rechnung im variabilný symbol übereinstimmt, sucht das Tool eine Rechnung mit demselben Betrag (innerhalb der Toleranz), deren Fälligkeit höchstens 45 Tage vom Zahlungsdatum entfernt liegt (in Pro einstellbar). Ist ein solcher Treffer der einzig mögliche, also nicht mehrdeutig zwischen mehreren Rechnungen oder Zahlungen, wird er als Vorschlag zum Abgleich angeboten.

Was sind Vorschläge?

Ein Vorschlag ist eine Zuordnung über Betrag und Datumsnähe ohne übereinstimmenden VS: weniger sicher als ein Treffer über den variabilný symbol, deshalb markiert das Tool ihn nicht automatisch als bezahlt. Er erscheint in der Liste Abgeglichen mit dem Hinweis „Vorschlag“ und wartet auf manuelle Bestätigung, zum Beispiel wenn der Kunde den VS bei der Zahlung falsch geschrieben hat.

Werden Daten gesendet?

Nein. Das Parsen von Auszug und Rechnungen sowie der Abgleich selbst laufen vollständig in Ihrem Browser, das Tool hat kein Backend. Die einzige Netzwerkaktivität ist das Laden der statischen Dateien der Seite, ein anonymer Nutzungszähler (Umami: nur Ereignisnamen und Anzahlen, nie der Inhalt von Auszug oder Rechnungen) und Ihre E-Mail-Adresse, wenn Sie sich unten freiwillig für Neuigkeiten anmelden.

Wie markiere ich Rechnungen in meinem Programm als bezahlt?

Die Liste Abgeglichen lässt sich als CSV „als bezahlt markieren“ (Rechnungsnummer, Zahlungsdatum, Betrag) herunterladen und in Ihr Buchhaltungsprogramm zurückimportieren. Ohne Lizenz werden die ersten 20 Zeilen als Beispiel in einer allgemeinen CSV heruntergeladen. Mit Lizenz die vollständige Datei und zusätzlich ein Spaltenformat in der Sprache von Pohoda, Omega oder Money S3. Keines davon ist ein geprüftes Importformat direkt vom Hersteller, nur eine Schätzung dieser Seite, prüfen Sie es also vor dem Import.
